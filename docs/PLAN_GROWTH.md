# Plan: growth measurements, milestones by age, and insights

**Status (2026-10-29): all phases are built and tested; see `docs/STATUS.md`. Changes from the plan:** a milestone answer is a `milestone` event instead of a `milestone_check` table, so it needs no server work; the Growth and milestones screen is its own screen, reached from the Growth card on Today, instead of living in Analytics; the switch for insight cards is `aiInsights` because `insights` already names the Coming up card; sleep intelligence (age-based goal, sleep-log checks, still-asleep alert) was added at the owner's request. Not yet done: a try with a real model and a phone.

Goal: the parent logs head, length and weight; sees the baby's milestones for their age; and gets short, cited insights built from this baby's own data, as info cards and a notification.

## Decisions

- **A measurement is an event.** New kind `measure` with optional `weightG`, `lengthMm` and `headMm` (at least one), stored metric. It rides the existing log, so sync, the household, the Timeline edit sheet, duplicate-free ids and the Say it box (`"weighed 6.2 kg, 62 cm, head 41"`) all work without a second pipeline. Display follows the `unit` setting (lb/in or kg/cm); nothing is stored twice.
- **Percentiles are optional.** A new shared setting `babySex` (`girl`, `boy`, unset). With it set, each measurement shows a WHO percentile and band. Unset: values and the baby's own trend only. Nothing is guessed (SPEC: never invent data).
- **Reference data is vetted and cited, not remembered by the model.** WHO growth standards (0 to 24 months, weight, length, head circumference, each sex) as LMS rows, and the CDC milestone checklists (2, 4, 6, 9, 12, 15, 18, 24, 30, 36 months). Both go in the database through versioned seeds (rule 9), with the source and review date in `src/knowledge/sources.ts`. The tables are fetched from the WHO and CDC publications and checked against them in tests; they are never typed from memory.
- **Milestones are checkable.** Each CDC item is a row the parent marks "yes / not yet / not sure" for the baby. Marks live in a `milestone_check` table and are shared with the household. The screen groups by the baby's age band, with the next band ahead. Not-yet items near the end of a band are listed under "worth raising at the next checkup" with the CDC line to ask about screening. No diagnosis, no "delay" label.
- **"Agentic RAG" means tools that retrieve this baby's data, not a vector database.** The corpus is small and structured, so retrieval is by age and topic, as `pediatric_guide` already does. The chat agent gets `getGrowth` (measurements, percentiles, trend) and `getMilestones` (this baby's marks plus the CDC items for the age band), next to the tools it has. Every figure in an answer comes from a tool result.
- **Insights are generated by the model from those tools, then checked.** A new `insights` mode on `/api/agent` runs the same tool loop with a fixed brief ("one growth note, one milestone note, one rhythm note, each with its evidence and source") and returns Zod-validated cards: `{ id, topic, title, body, sources[] }`. Insight text is data: it is shown, never executed, and the same safety rules apply (not a doctor; red flags lead with the pediatrician).
- **Push is on-device first** (owner's choice). When the app opens or returns to the front, at most once a day and only if a new measurement, milestone mark or birthday-band change happened, it asks for insights, saves them as cards (`insight` table) and shows one local notification (`notifyNow`). It does not wake a closed app. Real server push (FCM, device tokens in Turso, a cron) is a later phase if wanted.
- **WebMCP gets the same data** (`src/webmcp.ts`, the existing four tools stay as they are). Four new tools for the browser's assistant:
  - `log_measurement` (writes): `weightKg?`, `lengthCm?`, `headCm?`, `when?` (ISO time, defaults to now), at least one value. A structured input is safer than parsing a sentence for numbers with units. It checks the same ranges as the `measure` event, logs through the normal path with Undo ("Assistant: Logged..."), and answers what was stored. `log_baby_event` also learns measurement phrases from the same parser.
  - `get_growth` (read-only): the latest value of each measurement, change since the previous one, and the WHO percentile when the sex setting is set. Without it the answer says percentiles need the setting.
  - `get_milestones` (read-only): the CDC items for the baby's age band with the parent's marks, and the "raise at the next checkup" list.
  - `get_insights` (read-only, `untrustedContentHint`): the latest saved insight cards. They are model-written text, so the assistant is told to treat them as data.
  - Marking a milestone is not offered to the assistant. It is the parent's own judgment about the baby, so it stays a tap in the app.
  - Input is Zod-checked and strict like `log_baby_event`; amounts are capped, and a value outside the range is refused with the reason, never clamped. Nothing is exposed to other origins, and browsers without `document.modelContext` are unaffected.
- **Cost and safety guards:** insights run only when signed in and online; one call per day per baby; the request carries measurements, milestone marks and the recent events already sent today, nothing else. Without the model key the cards are simply absent and every other screen works.
- **No new package.** Charts reuse the SVG used on the Analytics tab; storage reuses `node:sqlite`/Turso/libSQL already in place (rule 8).

## Phases

1. **Measurements.** `measure` event, parser phrases, Log tab "Growth" form, Timeline entry and edit, a Growth screen (latest values, simple line charts, unit switch). Done when: a typed sentence and the form both create the same event; unit display switches without changing stored values; an impossible value (weight 60 kg) is refused, not stored; two phones see the same measurement after one sync.
2. **Percentiles.** `babySex` shared setting, WHO LMS seed, `percentile()` and a band label. Done when: values at the WHO median give 50, tests use published table rows, and an unset sex shows no percentile.
3. **Milestones by age.** CDC seed, `milestone_check` table and sync, Milestones screen by age band, "raise at the next checkup" list. Done when: marking an item survives a reload and reaches the other phone, and a band with no marks shows its items unmarked.
4. **Agent tools.** `getGrowth`, `getMilestones`, prompt rules, evals. Done when: a stubbed-model test shows the tools return only stored values, and the WebMCP `schema.json` stays identical to the registered tools.
5. **WebMCP.** The four tools above, with handlers wired in `App.tsx` beside the existing ones, new cases in `evals/webmcp/evals.json` (for example "She weighed 6.2 kg and measured 62 cm today" expects `log_measurement` with `weightKg` 6.2 and `lengthCm` 62; "How is her weight tracking?" expects `get_growth`; "What should she be doing at 6 months?" expects `get_milestones`; "Any new notes about her growth?" expects `get_insights`) and `schema.json` regenerated. Done when: `npm test` shows `schema.json` identical to the registered tools and every case passes; an out-of-range or unknown field is rejected; `log_measurement` shows the Assistant line with Undo; the smoke run (`npm run evals:webmcp:smoke`) calls each new tool on the live page in Chrome Canary. The model-driven run needs a key and is not part of `npm run check`.
6. **Insights.** `insights` mode, validation, `insight` table, info cards on Today, once-a-day trigger, local notification, switches `insights` and `alertInsights` in Profile. Done when: with the stub model, a new measurement produces cards and one notification; no new data produces none; a malformed model reply is dropped, not shown. This phase also adds the `get_insights` WebMCP tool and its eval case, since the cards do not exist before it; phase 5 ships the other three.
7. **Docs.** `STATUS.md` (including the WebMCP tool list and eval count), `ARCHITECTURE.md` (decision lines), `src/knowledge/README.md` (growth and milestone content, review dates).

## Open before phase 2 and 3

- WHO LMS tables and CDC checklist text need to be fetched and checked against the source pages. Licence: WHO standards are free to use with attribution; the CDC pages are public domain.
- Whether prematurity (corrected age) matters for this baby. The first version uses the birth date only and says so.

## Not in scope

Server push to a closed app, growth charts for children over 2 years (CDC curves), photos with milestones, and sharing insights outside the household.
